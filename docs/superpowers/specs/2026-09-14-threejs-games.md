# 六款游戏的 Three.js 场景

目标：修复当前合并损坏，保留已有玩法与本地存档，将六款游戏的主要场景接入真实可交互的 Three.js 渲染。

## 视觉与交互

- 沿用转转刀的低多边形国风，把游戏世界呈现为可转动的掌中仙境。
- 色板：松青 `#173d41`、玉绿 `#57b7a6`、鎏金 `#dbb46b`、墨蓝 `#101e32`、雾青 `#cbdce2`、朱砂 `#cf725f`。
- 标题沿用现有霞鹜文楷，正文沿用系统中文字体；数据使用等宽数字。
- 修仙之路：云台、修士与境界光环，修炼状态和修为进度直接驱动画面。
- 仙途模拟器：随年龄和境界变化的庭院；事件选项形成可点选的道路。
- 鬼谷八荒：真实地图、探索迷雾、目的地与路线；选点后逐格前进并照常触发遭遇。
- 斩仙塔：分支节点、连线、敌人意图与手牌；所有动作进入原有战斗规则。
- 灵卡对决：双方仙师、随从、手牌和合法目标，保留嘲讽、费用与施法限制。
- 仙卡录：真实五人阵容与自动战斗，角色生命和大招状态同步到模型。

## 结构

每页只有一个 WebGL 上下文。UMD 状态转换模块生成只读视图数据；入口负责把真实游戏动作接入场景。ES modules 管理摄像机、资源、对象、拾取和场景构建。

HTML 保留文字说明、存档、操作面板与键盘入口。场景提供触控、鼠标和键盘选取，支持缩放、转动、复位及减少动态效果偏好。

使用现有本地 Three.js 0.186.0；所有页面、共享资源及传递导入统一升级至 v34 并预缓存。图形错误显式显示；隐藏页面停止绘制，退出时释放几何体、材质、纹理和事件监听。

## 验收

恢复全部原有测试，增加真实状态映射、合法操作与拾取回归检查；运行 JS 语法及完整预缓存校验。浏览器逐页验证开局与核心交互，检查手机布局和实际离线加载。

## 验收记录（2026-09-15）

- 自动检查：`npm test` 的 44 个测试文件全部通过；预缓存检查覆盖 163 个资源、9 个页面；170 个 JavaScript 文件通过 `node --check`。
- 真实交互：修仙打坐与攻击、仙途事件选择与年龄推进、鬼谷地图移动与天数扣除、斩仙塔分支选路与出牌、灵卡对决召唤、仙卡录换将与目标选择均在浏览器验证。
- 大招回归：仙卡录等待大招时切换敌人目标，原大招按钮和回调保持有效；点选三维剑尊后实际释放大招并获胜。对应单元回归验证目标切换、取消及按钮唯一性。
- 转转刀回归：开局、敌人生成、击杀、移动、闪避和暂停继续均通过；渲染器为本地 Three.js r186。
- 手机布局：390 像素视口下，七款游戏均无页面横向溢出；新场景在战斗期间挂载到对应战斗区域。
- 离线加载：同时断开页面与当前、后续启动的 Service Worker 网络并关闭 HTTP 缓存，门户及七个游戏入口正常加载；未缓存地址实际返回带 `<base>` 的离线页面。
- 离线资源：角色立绘、鬼谷地形、斩仙塔与灵卡对决图符、本地 Three.js 均可从 CacheStorage 读取；实际缓存为 `xianjieyoufang-v34`，含 163 项。
- 离线玩法：转转刀实际推进 30 帧，角色横向移动 78 个游戏单位并暂停；仙卡录第一章连续打完三波，击败首领并产生“战斗胜利！”结算日志。验收期间未捕获 JavaScript 异常。
